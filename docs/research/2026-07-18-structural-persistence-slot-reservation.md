# 구조 지속성(자리 예약) — 런타임 마운트/언마운트에도 다이어그램 골격을 유지하기

- 작성: 2026-07-18
- 상태: **조사/방향 메모(미구현)** — 사용자 요청으로 아이디어를 기록만 해둔다. 실제 구현은 레이아웃 안정성 라운드(리스트 접기 → downfall → 공유 레인) 이후 재검토.

## 문제

렌더 트리 구조는 **개발자가 코드를 바꾸지 않아도 런타임에 바뀐다** — 사용자 인터랙션이나 데이터 도착으로:

- **모달 열기** → PortalModal 콘텐츠 마운트 → 그룹 등장
- **탭 전환** → 한 서브트리 언마운트, 다른 서브트리 마운트
- **라우트 이동** → 페이지 통째 교체
- **비동기 데이터 도착** → 섹션 마운트

즉 다이어그램은 "구간별 정지(piecewise-stable)"다 — 이벤트 사이엔 완전히 정지, 이벤트 순간에만 변한다. 문제는 이 순간마다 **개발자가 처음부터 봐 온 다이어그램 골격이 바뀌어**(그룹이 나타났다 사라지고, 위치가 재배치되고) 방향 감각을 잃을 수 있다는 것이다.

## 아이디어 — 자리 예약(slot reservation)

마운트/언마운트를 **골격에서 지우지 않고, 그 자리를 예약해** 다이어그램 구조를 안정적으로 유지한다:

- **언마운트된 노드/그룹은 즉시 지우지 않는다** — 자리를 비운 채 "지금 없음(dormant)" 상태로 흐리게 남긴다(placeholder/ghost). 탭을 다시 열거나 모달을 다시 띄우면 같은 자리에 되돌아온다.
- **한 번이라도 본 구조의 합집합(union)을 골격으로** 삼는다 — "이 앱이 가질 수 있는 전체 구조"의 안정된 지도. 현재 마운트된 부분만 진하게, 나머지는 예약된 빈 자리로.
- 결과: 모달을 열든 탭을 바꾸든 **골격은 그대로**, 그 자리의 노드만 활성↔dormant로 바뀐다. 개발자의 공간 기억이 깨지지 않는다.

## 검토할 갈래

1. **얼마나 오래 예약을 유지하나** — 세션 내내(합집합 계속 누적) vs TTL(오래 안 돌아오면 반납) vs 라우트 경계에서 리셋. 무한 누적은 라우팅 많은 앱에서 골격이 비대해진다(ADR-0018의 `groupOrder` pruning이 정확히 이 문제로 도입됐음 — 상충 주의).
2. **dormant 표현** — 흐림/점선/체크무늬. 이미 `group-node--collapsed`(지도 모드 접힘)와 시각적으로 구분돼야 한다.
3. **어느 레이어에 둘까** — 데이터(RenderNode) 밖의 "관측 이력" 레이어. `interactionStore`처럼 스키마 불변으로 얹기(ADR-0026 패턴). 라이브 스냅샷 위에 "지금까지 본 노드 union"을 유지하는 별도 store.
4. **downfall 안정성과의 관계** — 자리 예약은 barycenter 재배치 연쇄를 근본적으로 없앤다(구조가 안 바뀌니 부모 x도 안 움직임). 즉 이 기능은 레이아웃 안정성의 "상위 호환" 해법이다 — 다만 union 골격이 비대해지는 새 비용을 진다.

## 지금 결정

**미구현.** 먼저 저비용 안정성 조치(리스트 접기 → downfall order-once → 공유 레인)로 대부분의 요동을 잡고, 그래도 "이벤트 순간의 골격 변경"이 실사용에서 거슬리는 게 확인되면 이 자리 예약을 얹는다. 근거: CLAUDE.md "막힌 증거 없이 먼저 하지 않는다" + `groupOrder` pruning(ADR-0018)과의 상충을 실측으로 저울질해야 함.
