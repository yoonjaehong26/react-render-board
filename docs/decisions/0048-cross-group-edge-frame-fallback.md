# ADR-0048: 크로스-그룹 간선 프레임 폴백 — 확대해도 도메인 연결이 안 사라지게

- 상태: 채택됨(구현, 버그 수정)
- 날짜: 2026-07-18

## 맥락 (Context)

사용자가 버그를 리포트했다: **"wide view에선 보이던 간선이 확대하면 사라진다."** 실측으로 재현·특정했다(`.zoom-badge`/`.canvas` 대역 + 간선 DOM 카운트):

```
z=61% mid | 크로스-그룹 간선 14개 (보임)
z=73% mid | 크로스-그룹 간선 0개  ← DOM에서 통째로 사라짐(opacity 0이 아니라 미생성)
```

원인: 크로스-그룹 간선(부모 그룹 A → 자식 그룹 B의 진입 노드)은 `toFlow`가 **양쪽 노드가 둘 다 펼쳐졌을 때만** 만든다(`expandedIds.has(n.id) && expandedIds.has(n.parentId)`). 그런데 확대하면 뷰포트 기반 부분 재계산(ADR-0017)의 `shouldExpandGroup`이 **화면 밖 그룹을 안 펼친다** → 부모(예: app-root `DemoApp.tsx` 그룹)가 화면 위로 나가면 그 노드가 컬링돼 `expandedIds`에서 빠지고 → 간선이 아예 안 만들어진다. 지도 모드에선 그룹↔그룹 집계 엣지(`edge-group-link`, ADR-0034)가 연결을 보여주지만 상세 모드에선 그게 숨겨지므로, "확대하니 연결이 사라지는" 구멍이 생겼다.

## 결정 (Decision)

**부모 노드가 컬링됐을 때 크로스-그룹 간선을 버리지 않고, 부모의 "그룹 프레임"으로 잇는다**(그룹 프레임은 `toFlow`가 뷰포트와 무관하게 항상 렌더한다 — 자식 노드만 컬링, 프레임은 유지).

`toFlow` 간선 생성 로직을 바꿨다:
- 필터를 `expandedIds.has(n.id)`(자식만)로 완화한다.
- 부모까지 펼쳐졌으면 → 정확한 **노드↔노드** 간선(기존).
- 부모 노드가 컬링됐으면(= 크로스-그룹에서만 발생. 같은-그룹은 그룹 단위 all-or-nothing이라 자식이 펼쳐졌으면 부모도 펼쳐졌다) → **부모 그룹 프레임 → 자식** 폴백 간선(`group:{부모그룹}->{자식id}`, 새 클래스 `edge-cross-group-frame`). 부모 그룹 프레임이 실제 렌더된 경우에만(pending·검색 필터로 빠진 그룹 제외).

폴백 간선도 점선(`edge-cross-group`) + 부모 도메인 색(`edge-parent-palette-N`, ADR-0047)이라, "저쪽(화면 밖) 도메인에서 이 노드로 들어온다"가 확대해도 계속 읽힌다.

## 근거 (Rationale)

- **연결 정보는 위치보다 중요하다.** 크로스-그룹 간선은 "어느 도메인이 이 도메인을 렌더하나"라는, 위치로 예측 불가능한 고정보 신호다(ADR-0041에서 감쇠 대상에서 뺀 이유). 이게 확대 시 사라지면 지도→상세 전환의 연속성이 깨진다.
- **프레임은 이미 항상 있다.** ADR-0017이 "화면 밖 그룹은 프레임만, 자식은 안 만든다"로 설계돼 있어, 프레임 폴백은 새 노드를 안 만들고 이미 있는 프레임에 잇기만 한다 — 성능 불변식(배열 크기 = React Flow 비용)을 안 건드린다.
- **크로스-그룹에만 적용돼 안전하다.** 같은-그룹은 자식이 펼쳐졌으면 부모도 펼쳐졌으므로 폴백 경로에 도달하지 않는다(그룹 단위 펼침). 폴백은 정확히 "부모가 다른 그룹이라 따로 컬링될 수 있는" 경우만 잡는다.
- **집계 엣지(ADR-0034)와 안 겹친다.** `edge-group-link`(프레임↔프레임)는 상세 모드에서 CSS로 숨겨지고, 폴백은 프레임→노드라 엔드포인트가 달라 이중선이 안 생긴다.

## 결과 (Consequences)

- **실측 회귀 해소**: z=61%→73%에서 크로스 14→**0**이던 것이 14→**6(전부 프레임 폴백)**으로, 확대해도 유지된다. 결정적 확인: DeepTree의 `Level1` 진입 노드에 `group:DemoApp.tsx->382`(프레임 폴백, opacity 1) 간선이 들어온다.
- **신규**: `scripts/verify-edge-frame-fallback.mjs`(`npm run verify:edge-frame-fallback`) — 초기(far)에서 상세 모드로 확대하며 크로스-그룹 연결이 0으로 붕괴하지 않고, 부모 컬링 시 프레임 폴백이 생성되는지 검증. `edge-cross-group-frame` 클래스.
- **유닛 테스트 갱신**: "부모만/자식만/둘 다 펼침" 테스트를 새 동작(자식만 펼치면 프레임 폴백 1개 생성, source=`group:A`)에 맞게 고쳤다.
- **엔드포인트 전환 시 재마운트**: 부모가 화면에 들락날락하면 간선 id가 `parentId->childId` ↔ `group:parentGroup->childId`로 바뀌어 React Flow가 재생성한다(경계에서 미세한 깜빡임 가능하나, 연결 자체는 계속 보인다). 허용 범위로 판단.
- **hover 혈통(ADR-0044)과의 관계**: 혈통 탐색은 `group:` 접두 엔드포인트 간선을 건너뛰므로, 프레임 폴백 간선은 혈통 점등에 포함되지 않는다(부모가 어차피 화면 밖이라 실익 적음). 남겨둔 알려진 한계.
