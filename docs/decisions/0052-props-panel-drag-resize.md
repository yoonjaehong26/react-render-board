# ADR-0052: props 패널 드래그 이동 + 크기 조절

- 상태: 채택됨(구현)
- 날짜: 2026-07-18

## 맥락 (Context)

노드를 선택하면 뜨는 props 패널(ADR-0032)은 `.canvas` 우측에 세로로 꽉 찬 고정 창(`right:12; width:280px`)이었다. 사용자 피드백: **"props 리스트 모달이 화면을 많이 가린다. 전체 레이아웃 패널(ADR-0040)처럼 크기·위치를 조절하게 하자 — props가 많아질 것도 고려해서."** 실제로 props가 많은 컴포넌트(예: DataFlowList)에선 280px 폭이 좁아 값이 잘리고, 우측 고정이라 그 자리의 다이어그램을 늘 가린다.

## 검토한 대안 (Options)

- **도킹 패널(ADR-0040)처럼 좌/우/하단 도킹 + 비율 크기** — 도킹 패널은 앱 옆에 붙는 큰 영역이라 방향(dock)이 핵심 축이지만, props 패널은 캔버스 *위를 덮는 작은 창*이라 "어느 가장자리에 붙나"보다 "어디로 치우고 얼마나 키우나"가 자연스럽다. 도킹 모델을 그대로 재사용하면 오히려 어색하다.
- **자유 이동(드래그) + 자유 크기(리사이즈 핸들)** — 채택. 헤더를 잡고 아무 데나 옮기고, 좌하단 핸들로 폭·높이를 늘린다. 가리는 위치를 사용자가 직접 피하고, props가 많으면 넓게/길게 편다. 좌표/크기는 `.canvas` 기준 px로 localStorage에 기억.

props 패널의 성격(작은 떠다니는 창)엔 자유 배치가 도킹보다 맞고, 구현도 컴포넌트 안에 갇혀(Canvas 불변) 국소적이라 택했다.

## 결정 (Decision)

**`PropsPanel`이 자기 위치·크기를 상태로 들고, 헤더 드래그(이동)와 좌하단 핸들(리사이즈)로 갱신하며 localStorage에 영속한다.**

- **좌표계**: `.canvas`(부모 요소) 기준 `{x, y, width, height}` px. 마운트 시 `useLayoutEffect`가 컨테이너 크기를 재서 저장값(없으면 우측 정렬 기본값)을 `clampLayout`으로 죈다 — 마운트 전 잠깐은 기존 CSS 기본 위치로 그려져 깜빡임이 없다.
- **드래그**: 헤더에 `pointerdown` → `window`의 `pointermove/up`으로 추적, 이동량을 시작 좌표에 더해 clamp. 닫기 버튼 클릭은 `closest('.props-panel__close')`로 걸러 드래그로 삼키지 않는다.
- **리사이즈**: 좌하단(SW) 핸들 — 오른쪽 변 고정, 왼쪽 변이 이동(폭이 안쪽으로 커지고 x가 따라감) + 아래 변이 이동(높이). 우측 도킹 기본 위치에서 "안쪽으로 넓히기"가 자연스러운 방향이라 SE가 아니라 SW를 골랐다.
- **clamp**: 최소 크기(220×140) 보장 + 컨테이너 밖으로 못 나가게(창 크기가 달라져도 불러올 때 다시 clamp). 좌표는 방향 무관 px라 도킹 패널의 "비율" 저장과 달리 단순.
- **영속**: `propsPanelPreference.ts`(get/set/clamp/default) — `colorModePreference`/`panelLayoutPreference`와 같은 얇은 try/catch 패턴. 세션 보조가 아니라 사용자가 정한 작업 공간이라 영속화한다(도킹 패널과 같은 판단).

## 근거 (Rationale)

- **가림 문제의 직접 해소.** 사용자가 가리는 위치를 피해 옮기고, props가 많으면 폭·높이를 키운다 — "많이 가린다 + props 많아질 것"에 정확히 대응.
- **Canvas 불변.** 위치/크기/드래그/영속을 전부 `PropsPanel` 안에 가둬 Canvas(대형·다중 세션 공유 파일)를 건드리지 않는다 — 충돌 위험 최소.
- **기존 자산 재사용.** 저장 모듈은 도킹 패널과 같은 패턴, 좌표계는 이미 `.canvas`가 `position:relative`라 `position:absolute` 자식이 그대로 얹힌다.

## 결과 (Consequences)

- **바뀐 것**: `PropsPanel.tsx`(위치/크기 상태 + 드래그·리사이즈 핸들러 + 헤더 그립/리사이즈 핸들 DOM), 새 `propsPanelPreference.ts`(+테스트), `flow.css`(`.props-panel__header--draggable`/`__grip`/`__resize` + 다크모드). props 데이터/정렬/추적(ADR-0032) 로직 불변.
- **검증**: `tsc` 클린, 유닛 304개 통과(신규 preference 5개 포함 — clamp/default/저장 왕복/깨진 값 null). Playwright 실측 — 헤더 드래그로 -250px 이동, 좌하단 핸들로 폭 +148px, 새로고침 후 좌표·크기 그대로 복원, 콘솔 에러 0. 세로 이동/리사이즈는 도킹된 보드 영역이 짧을 때 clamp로 고정되는 게 정상(패널이 컨테이너 높이를 거의 채움).
- **되돌리기 쉬움**: 저장값이 깨졌거나 없으면 우측 정렬 기본값으로 복귀 — 예전 고정 배치와 사실상 동일.
- **남긴 것**: 리사이즈 핸들은 좌하단 한 곳뿐(4방향 아님). 기본 우측 도킹엔 충분하고, 필요해지면 방향을 늘린다(과설계 회피, CLAUDE.md 원칙).
- **관련 문서**: props 패널 [ADR-0032](0032-props-flow-and-change-afterglow.md), 도킹 패널 크기/위치 영속 [ADR-0040](0040-resizable-dockable-panel.md).
