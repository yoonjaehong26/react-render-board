# ADR-0047: 간선 색 = 부모 도메인, 상시 적용 (ADR-0044 "hover에서만" 뒤집음)

- 상태: 채택됨(구현)
- 날짜: 2026-07-18

## 맥락 (Context)

[ADR-0044](0044-hover-lineage-highlight.md)에서 "간선을 부모(출발) 노드의 도메인 색으로 칠하는 건 **hover 혈통 때만** 하고, 상시로는 하지 않는다"고 결정했다. 근거는 "상시 전면 채색은 [ADR-0041](0041-edge-clutter-attenuation.md)의 감쇠(그룹 내 간선 잉크 죽이기)를 되돌려 클러터를 복원한다"였다.

원 채팅에서 사용자가 이 근거를 반박했다: **"이미 opacity로 감쇠해놨으니 색 채널에서까지 감쇠할 필요는 없다. 같은 파일 안에서는 분류할 필요가 없으니 오히려 색으로 통일하면 가독성이 오르지 않나?"** 이 지적이 ADR-0044의 "haze" 논리의 결함을 드러냈다.

## 결정 (Decision)

**모든 노드 레벨 간선을 상시로 "부모(출발) 노드의 도메인 색"으로 칠한다.** hover 한정을 푼다. 간선의 세 시각 채널을 서로 직교하게 나눈다:

| 채널 | 의미 | 근거 ADR |
|---|---|---|
| **opacity** | 그룹 내 깊이 감쇠(깊을수록 옅게) | ADR-0041 a |
| **hue(색)** | 부모(출발) 노드의 도메인 팔레트 색 | 이 ADR |
| **선 스타일** | 그룹 내=실선 / 그룹 경계=점선 | ADR-0034 + 이 ADR |

- 구현: `toFlow`가 모든 노드 간선에 `edge-parent-palette-{0..7}`(= `colorIndexForGroup(부모.group)`)을 상시로 붙이고, CSS가 그 색으로 stroke를 준다(`!important` 없음 — hover 혈통·props 흐름 장식의 강조가 이김). pending 그룹은 색 미배정(폴백 회색).
- **크로스-그룹 간선의 주황 단색을 없앤다.** 경계 신호는 이제 색이 아니라 **점선(`stroke-dasharray`)** 이 맡고, 색은 부모 도메인을 나른다 — "어느 도메인이 이 도메인을 호출했나"가 상시로 읽힌다.
- 감쇠(opacity)는 **그대로**다. 색은 hue 채널에만 얹혀 감쇠를 되돌리지 않는다.

## 근거 (Rationale)

- **haze 논리가 틀렸다: 간선은 "부모 도메인" 색이라 그룹 내부는 단색이다.** ADR-0044의 "상시 채색 = 무지개 haze" 우려는 "여러 색이 섞인다"를 가정했다. 그러나 같은-그룹 간선은 부모가 그 그룹 안에 있으므로 **한 그룹의 내부 간선은 전부 그 그룹의 단일 색**이다. 여러 색이 만나는 건 그룹 경계(크로스-그룹, 소수)뿐이다. 즉 국소적으로는 무지개가 아니라 도메인별 단색이라, 회색보다 오히려 figure-ground(어느 도메인의 배선인가)가 좋아진다.
- **감쇠와 색은 독립 채널이다.** 낮은 opacity가 이미 "조용함"을 담당하므로, 그 위에 hue를 얹는 건 "잉크(주목도)"를 크게 늘리지 않고 정보(도메인 정체성)만 더한다. 사용자의 핵심 통찰 — "opacity로 감쇠했으면 색까지 감쇠할 필요 없다".
- **크로스-그룹 정보가 늘어난다.** 기존 주황 단색은 "경계 넘음"만 알렸다. 부모 도메인 색 + 점선은 "경계 넘음(점선) + 출처 도메인(색)"을 둘 다 준다 — 정보량이 순증한다.
- **실측으로 확인.** 라이트/다크 모두에서 AppShell.tsx 그룹 내부 간선이 cyan 단색으로 응집되고, app-root→AppShell 크로스-그룹 간선이 blue 점선으로 드러났다(`verify-output/edge-parent-color/`). haze 없이 읽혔다.

## 결과 (Consequences)

- **ADR-0044의 "부모 색은 hover에서만" 결정을 이 ADR이 뒤집는다.** ADR-0044의 나머지(hover 혈통 점등: 조상+자손 간선을 굵게+강조, 나머지 dim)는 유효하다 — hover는 이제 "상시 도메인 색"을 **더 굵고 진하게 키우는** 강조로 작동한다(색 규칙은 공유, hover는 width/!important로 승격).
- **크로스-그룹 주황이 사라진다.** 노드의 주황 box-shadow(`.component-node--cross-group`)는 유지되므로 "경계 노드" 신호는 남고, 간선 쪽 경계 신호는 점선으로 이관됐다.
- **구현 정리**: hover 전용이던 `colorIndexById`(Canvas)를 제거하고 색 부여를 `toFlow`로 옮겼다(정적 구조 속성이라 그 자리가 맞다). `flowEdgesDecorated`의 `withLineage`는 이제 `edge-lineage`만 얹는다.
- **검증**: `verify-edge-clutter`(감쇠·LOD)·`verify-edge-lineage`(hover 강조) 둘 다 회귀 없이 통과. 유닛 테스트는 className 정확 매치 → 토큰 포함(`toContain`)으로 완화(팔레트 접미사 수용).
- **되돌리기 쉬움**: 순수 CSS/클래스라 데이터·레이아웃 불변. 상시 색이 특정 앱에서 과하면 opacity/채도만 조절하거나 크로스-그룹만 상시로 되돌릴 수 있다.
- **연결**: 다른 세션이 올린 [ADR-0045](0045-multi-props-flow-parent-colored-edges.md)(데이터 흐름 간선도 출발 노드 색)와 **같은 색 언어**를 공유한다 — 구조 간선(이 ADR)과 데이터 흐름 간선(ADR-0045)이 "간선 색 = 출발 노드 도메인"으로 일관된다.
