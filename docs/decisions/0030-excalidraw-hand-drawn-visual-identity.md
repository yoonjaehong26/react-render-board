# ADR-0030: Excalidraw풍 손그림 시각 정체성 — "역할별로 세기를 조절하는 하나의 손그림 언어"

- 상태: 채택됨. 다크 테두리·강조 마커/햇칭·볼펜 크롬·워드마크 마크업 **구현됨**([ADR-0035](0035-shape-and-hand-drawn-implementation.md)). 워드마크 OFL 폰트 에셋(오프라인 미확보, 시스템 손글씨 폴백)과 그룹 프레임 rough(프로파일링 후)만 잔여.
- 날짜: 2026-07-18

## 맥락 (Context)

사용자가 NestJS Devtools식 "어두운 테마 + shadcn 기본 스타일"을 싫어하고 Excalidraw풍 손그림 + 과감한 색을 이 도구의 시각 정체성으로 원한다는 데서 출발했다. 이미:

- 컴포넌트 노드에 rough.js 손그림 테두리가 구현·검증됐고(b3f8eb9, `roughStyle.ts` — 노드 크기가 고정이라 정적 SVG 2장을 모듈 로드 시 1회 생성해 공유, 노드 수 무관 O(1)),
- 도메인 팔레트/다크모드가 구현됐으며([ADR-0027](0027-search-and-theme-ux-round.md)),
- 조사([`../research/2026-07-18-excalidraw-visual-identity.md`](../research/2026-07-18-excalidraw-visual-identity.md))가 rough 값·색·폰트·spacing을 실제 Excalidraw 소스에서 확인해 후속 결정거리를 제시했다.

이 ADR은 그 후속 결정거리(손글씨체 범위 / 크롬 처리 / 다크 테두리 / 그룹 프레임 rough)를 원 채팅 논의로 확정한 것이다. **논의 과정에서 조사의 두 제안(무채색 크롬, 손글씨체를 라벨에)을 뒤집었고, 그 근거를 남기는 게 이 ADR의 핵심이다.**

## 검토한 대안 (Options)

### 축 1 — 손글씨 폰트를 어디에 쓸까

- **다이어그램 라벨(그룹명·컴포넌트명)에 손글씨(조사 제안)** — 기각. 조사는 "Excalidraw는 캔버스 콘텐츠에 손글씨를 쓴다 → 우리도 라벨에"라고 유추했으나 유추에 구멍이 있다: Excalidraw의 캔버스 텍스트는 사람이 자유롭게 쓰는 문장이지만, 우리 라벨은 `ComponentNode` 같은 **코드 식별자**다 — 정확히 읽혀야 하는 기술 토큰이라 모노스페이스가 맞고, 12px camelCase가 손글씨로 뭉개질 판독성 리스크도 있다.
- **로고/워드마크에만 손글씨(채택)** — Excalidraw 자신도 UI 크롬은 중립 폰트, 손맛은 캔버스 콘텐츠 + 로고에 둔다. 우리 도구에서 브랜드에 가장 가까운 지점은 "render-board" 워드마크(플로팅 버튼, 향후 헤더/빈 상태)다.

### 축 2 — 크롬(버튼/툴바)의 시각 처리

- **무채색 중립 크롬(조사 제안)** — 기각. "생기 있는 콘텐츠 vs 조용한 크롬"이라는 **대비** 모델인데, 손그림 캔버스와 sterile한 크롬이 오히려 이질적이다.
- **하나의 손그림 언어를 역할별 세기로(채택)** — rough.js는 흔들리는 스케치 하나가 아니라 스펙트럼이다(Excalidraw가 프리셋으로 코드화: architect=roughness 0 "깔끔한 볼펜", artist=1 "손그림", cartoonist=2 "만화풍" + fillStyle hachure/cross-hatch="햇칭", solid="마커"). "손그림 크롬"이 "지저분한 크롬"을 뜻하지 않는다 — 볼펜 끝(낮은 roughness)으로 그린 버튼은 손맛이 있으면서 또렷하다.

### 축 3 — 그룹 프레임에 rough를 적용할까

- 컴포넌트 노드의 "정적 이미지 2장 공유" 트릭은 노드 크기 고정에 의존하는데, 그룹 프레임은 크기가 제각각이라 그대로 못 옮긴다. → **지금 결정하지 않고, 프로파일링 후로 유보**(아래 결과 참고).

## 결정 (Decision)

**시각 정체성을 "역할별로 세기를 조절하는 하나의 손그림 언어"로 삼는다.** 손그림을 콘텐츠에만 쓰고 크롬은 중립으로 두는 대비 모델이 아니라, 도구 전체가 손그림 언어를 공유하되 rough 스펙트럼의 어느 지점을 쓰는지를 역할로 나눈다.

**타이포그래피(폰트 축):**
- 다이어그램 라벨(그룹명·컴포넌트명) → 모노스페이스(식별자 판독성).
- 기능 크롬(버튼/툴바/카운트/배지) → 모노스페이스.
- 로고/워드마크("render-board") → 손글씨 폰트 액센트 한 곳.

**손그림 처리(선/채움 축) — 역할별 세기:**

| 역할 | rough 세기 | 표현 |
|---|---|---|
| 다이어그램 노드 | artist(roughness ~0.8, 현행) | 스케치 — "지금 이 순간의 관찰" |
| 기능 크롬(버튼/툴바) | 볼펜(roughness ~0.2) | 손맛 있되 또렷 |
| 강조 상태(픽 모드 활성/검색 매치) | 마커/햇칭 채움 | "형광펜으로 짚은" 순간 |

**다크모드 러프 테두리:** `roughStyle.ts`의 정적 이미지를 2장 → **4장(라이트/다크 × composite/host)**으로 늘리고, 다크 변형은 `groupColor.ts`가 이미 검증한 다크 인디고(`#818cf8`)를 재사용한다(대비 3.7:1 → 5.5:1). 여전히 모듈 로드 시 유한 횟수(4회)만 계산 — 노드 수 비례 비용 0 유지.

## 근거 (Rationale)

- **식별자 ≠ 자유 텍스트.** 손글씨를 라벨에 쓰면 Excalidraw 유추는 맞아 보여도 우리 라벨의 성격(코드 토큰)과 안 맞는다. 개성은 rough 테두리 + 색/도형(ADR-0028)이 담고, 라벨은 판독성을 지킨다.
- **rough는 스펙트럼이다.** Excalidraw 자신이 architect/artist/cartoonist로 코드화한 그 스펙트럼을 역할별로 나눠 쓰면, "통일된 손맛"과 "기능 컨트롤의 또렷함"을 동시에 얻는다 — 대비 모델(무채색 크롬)보다 응집도가 높고 사용자 취향(손그림·색 적극 활용)에도 맞는다.
- **크롬 손그림은 성능상 공짜다.** 사용자가 visual-identity 문서 7~10절에 정리한 3레이어 성능 분석(① 다이어그램 O(n) / ② 패널 크롬 O(1) / ③ 호스트 위 플로팅 버튼·DOM 하이라이트 O(1~few))에 따르면 크롬·플로팅 버튼은 노드 수와 무관해, 라이브 rough.js를 써도 [ADR-0017](0017-viewport-based-partial-recompute.md)이 다룬 O(n) 제약이 적용되지 않는다.
- **손그림 미학은 이 도구의 정체성과 의미적으로 맞다.** 조사가 확인했듯 손그림은 "완성된 문서가 아니라 지금 대화 중인 것"이라는 신호다 — 커밋마다 바뀌는 살아있는 렌더 트리와 정확히 같은 결이다.

## 결과 (Consequences)

- **이미 구현됨**: 컴포넌트 노드 rough 테두리(artist 세기, b3f8eb9).
- **구현 완료([ADR-0035](0035-shape-and-hand-drawn-implementation.md))**: (a) `roughStyle.ts` 다크 대응 — route 6각형까지 포함해 6장으로, (b) 크롬(플로팅 버튼)에 볼펜 세기 rough, (c) 강조 상태 마커(픽)/햇칭(검색 매치) 채움, (d) "render-board" 워드마크 손글씨 마크업(`.rrb-wordmark`) — **단 OFL 웹폰트 woff2 에셋은 오프라인 환경에서 확보 못 해 시스템 손글씨 계열로 폴백 중**(`experiments/`의 `Virgil.woff2`는 검증용 사본이라 재사용 금지 — self-host `@font-face` 한 줄로 정식 에셋을 스택 맨 앞에 넣는 것만 남음).
- ~~**유보(프로파일링 후 결정)**: 그룹 프레임 rough.~~ → **적용됨([ADR-0035](0035-shape-and-hand-drawn-implementation.md) 후속 수정, 사용자 피드백).** 여기서 예고한 그대로 "접힌/지도 모드 그룹은 그대로 두고, 펼쳐진 그룹만 크기별 메모이즈 캐시로 적용"했다 — 지도 모드 수백 프레임엔 rough를 안 그리고, 같은 크기(4px 버킷) 프레임은 계산을 재사용해 개수-비례 비용을 억제한다.
- **조사 제안을 2건 뒤집음**: 무채색 크롬 → 볼펜 세기 손그림 크롬, 손글씨 라벨 → 손글씨 워드마크 한정. visual-identity 조사 문서는 그대로 두되(조사 기록), 최종 결정은 이 ADR이 상위다.
- **되돌리기 쉬움**: 전부 프레젠테이션(색/질감/폰트)이라 ui-philosophy.md 기준 되돌리기 쉬운 영역. 데이터 스키마·레이아웃 불변식과 무관하다.
