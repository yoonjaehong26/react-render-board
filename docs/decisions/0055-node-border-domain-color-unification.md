# ADR-0055: 노드 테두리 도메인 색 통일 — 색 언어를 노드까지 확장 + 그룹선 색·라우팅 유예

- 상태: 채택됨(노드 테두리 통일 구현 완료 / 그룹선 색·라우팅은 결정하되 유예)
- 날짜: 2026-07-18

## 맥락 (Context)

[ADR-0047](0047-always-on-parent-colored-edges.md)로 **간선**이, [ADR-0030](0030-excalidraw-hand-drawn-visual-identity.md)로 **그룹 프레임 테두리**가 도메인 팔레트 색(groupColor.ts 8색)을 상시로 입었다. 하지만 **컴포넌트 노드**는 팔레트가 반쪽만 적용돼 있었다:

- 그룹 프레임 테두리 = 팔레트 색 ✓
- 노드: **배경만** 팔레트(10% 알파 tint), **테두리는 그룹과 무관한 고정 인디고** 손그림([roughStyle.ts] `nodeBorderImage`가 colorIndex를 안 받음).

사용자 지적: "그룹색=간선색인데 노드 색상(테두리)까지 통일하면 어느 도메인 소속인지 한눈에 보인다." 특히 **줌인으로 그룹 프레임이 컬링되면**(ADR-0017) 노드 테두리 색이 도메인 정체성의 **유일한 단서**가 된다([ADR-0048](0048-cross-group-edge-frame-fallback.md) 프레임-폴백 간선과 같은 동기).

## 결정 — 노드 테두리를 부모 도메인 색으로 (composite/route만)

`nodeBorderImage(kind, mode, isRouteEntry, colorIndex?)`에 **colorIndex(그룹 팔레트 인덱스)** 를 선택 인자로 추가한다:

- **composite / route(6각형)** 테두리는 그 노드가 속한 **도메인 팔레트 색**으로 그린다 → 간선·프레임과 같은 색.
- **host**는 색을 안 입히고 **중립 슬레이트 대시**를 유지한다. host는 DOM 프리미티브라 역할색을 주지 않고 kind 구분 언어(대시=host, ADR-0030)를 보존한다 — 도메인 정체성은 이미 프레임·배경 tint·부모 composite가 전한다.
- **colorIndex 미배정(pending 그룹)** 이면 기존 중립 인디고 테두리로 폴백. 기존 3인자 호출과 **하위 호환**(테스트·레거시 export 그대로).

### 위계 3단으로 (haze 방지)

프레임(진한 팔레트) > 노드 테두리(팔레트) > 배경 tint(10% 팔레트)의 3단 색 위계. **haze가 안 생기는 근거는 ADR-0047과 동일**: 그룹당 단색이라 한 그룹은 한 색 덩어리로 읽혀 오히려 그룹핑을 강화하고, 여러 색이 섞이는 지점(크로스-그룹)이 곧 신호다.

### 성능

정적-이미지 공유 원칙(ADR-0017/0030) 유지: **8색 × 2모드 × 2셰이프 = 32개**만 모듈 로드 시 미리 계산해 노드 수와 무관하게 공유한다(런타임 노드별 계산 0). colorIndex는 `% PALETTE_SIZE`로 순환해 8색 넘는 그룹도 안전.

## 유예한 결정 (Decided-but-deferred)

아래 둘은 **하기로 방향을 정했으나**, 지금 **downfall(부모→자식 하향 상속) 구조를 완성 중**이라 그룹 간선/배선을 건드리면 충돌 위험이 있어 **버스 통합(Phase 2, ADR-0054)과 함께/이후로 미룬다.** 여기 기록만 남긴다(코드는 버려도 결정은 안 버린다).

1. **그룹선(edge-group-link) 색 통일** — 지금 회색 무채색인 그룹↔그룹 집계 간선([ADR-0034](0034-group-level-waterfall-layout.md))을 **출발 그룹 팔레트 색**으로 칠해 지도 모드에서도 "어느 도메인이 흐름의 출발인가"를 일관되게 보인다. 싸고 일관성 이득이라 채택 방향.
2. **그룹선 경로 최적화(버스는 아님)** — 그룹선에 **다른 그룹 프레임 미통과 + 직교 경로 최적화**(ADR-0051 A* 축소판)를 적용. 단 **버스 병합은 안 한다** — 그룹선은 쌍당 1개라 희소하고 지도 모드에서만 보여 합칠 클러터가 없다(버스는 상세 크로스-그룹 간선의 문제). 과투자 방지(CLAUDE.md) 차원에서 색만 먼저, 라우팅은 필요 근거가 쌓이면.

## 위험 (Risks)

- **색 과다**: 노드까지 색이 붙어 밀집 화면이 시끄러울 수 있으나, 그룹당 단색이라 haze가 아닌 덩어리로 읽힌다(ADR-0047 논증 상속). 필요 시 노드 테두리만 채도 낮춘 변형으로 후퇴 가능(현재는 프레임과 동일 팔레트 hex 재사용).
- **되돌리기**: `nodeBorderImage` 4번째 인자를 안 넘기면 정확히 이전 동작. 순수 프레젠테이션이라 데이터/레이아웃 불변.
