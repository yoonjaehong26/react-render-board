# ADR-0045: 다중 props 흐름 + 간선 색 = 출발(부모) 노드 (방향성)

- 상태: 채택됨(방향성 — 멀티 추적 메커니즘은 지금도 가능, 완성형(평행 색 줄기)은 배선 라운드와 공동)
- 날짜: 2026-07-18

## 맥락 (Context)

[ADR-0032](0032-props-flow-and-change-afterglow.md)로 props 흐름 추적을 구현했지만 지금은 **한 번에 하나의 참조**만 추적한다(`trackedPropKey` 단일, 청록 한 색). 사용자가 "여러 props의 흐름을 동시에, 각각 구분되게 추적할 수 없나"를 물었고, 동시에 차후 배선(edge routing, [ADR-0029](0029-orthogonal-edge-routing-deferred.md) 보류·[ADR-0041](0041-edge-clutter-attenuation.md) 클러터 감쇠 선행) 작업에서 "**간선 색을 출발 부모 노드에 따라 다르게**" 하려는 계획이 있다.

이 둘은 한 몸이다: 여러 흐름을 색으로 구분하는 가장 자연스러운 기준이 "그 흐름이 **어느 부모에서 나왔나**"이고, 그건 배선이 구조 간선에 쓰려는 색 기준과 정확히 같다. 그래서 **색 스킴을 지금 한 번 정해** props 흐름과 구조 배선이 공유하게 한다.

**선례 있음**: [ADR-0044](0044-hover-lineage-highlight.md)가 이미 "노드 hover 시 조상/자손 간선을 **부모 도메인 색**으로 점등"을 구현했다 — "간선 색 = 부모"라는 언어가 이 도구에 이미 자리잡았다. 다만 그건 **구조 혈통을 hover로 잠깐** 보는 것이고, 이 ADR은 그 같은 색 언어를 **데이터 흐름을 여러 개 상시 추적**하는 쪽으로 확장한다(hover=구조 혈통 / 추적=데이터 흐름, ADR-0032/0044의 상보 관계 연장).

## 검토한 대안 (Options)

### 흐름 색의 출처
- **(a) 출발 노드가 속한 그룹 팔레트색(도메인색, groupColor.ts)** — 이미 도메인=색이 있어 일관되나, 같은 도메인에서 나온 두 흐름은 색이 겹친다.
- **(b) 출발 노드 id 해시 → hue** — 부모마다 고유색. 도메인색과 별개 축이라 팔레트 충돌(검색 초록/추적 청록/역할색) 주의 필요.
- **(c) 트랙 순서 고정 팔레트(1번=빨강, 2번=파랑…)** — 구분은 쉽지만 "부모색"이라는 의미가 없어 배선과 공유 불가.
- **채택: (a)/(b)를 합친 "출발 노드 파생 단일 색 함수"** — 정확한 정의(도메인색이냐 노드 해시냐)는 배선 착수 시 구조 간선과 함께 확정한다. 지금은 "**간선 색 = 출발/부모에서 파생, props 흐름과 배선이 공유**"라는 원칙만 못박는다.

### 같은 간선을 여러 흐름이 지날 때
- **한 색만(우선순위)** — 배선 전 타협안. 겹친 간선은 대표 흐름 하나의 색.
- **점선 번갈아** — 두 색을 교대 dash로. 배선 전 차선.
- **평행 색 줄기(오프셋)** — 같은 부모→자식 사이에 여러 색 선을 나란히. **완성형**이지만 오프셋 배치가 필요해 **배선(라우팅)이 선행**돼야 한다.

## 결정 (Decision)

1. **간선 색 = 출발(부모) 노드에서 파생한 색**을 props 흐름과 (미래) 구조 배선이 공유하는 단일 색 함수로 둔다. 구현은 배선 착수 시 함께.
2. **다중 props 흐름 추적**: 추적 상태를 단일에서 **리스트**로 확장한다(`tracks: [{ 출발노드, propKey, 멤버 집합, 색 }]`). props 패널에서 추적 가능 행 클릭 = 그 흐름을 토글로 추가/제거. 각 흐름은 출발 노드 파생 색으로 그려진다. 이 메커니즘 자체는 배선 없이도 지금 구현 가능하다.
3. **겹침**: 배선 전에는 "한 색(우선순위) 또는 점선 번갈아"로 타협하고, **평행 색 줄기(완성형)는 배선 라운드에** 함께 만든다.

## 근거 (Rationale)

- **시각 언어 통일**: "이 부모에서 나온 것"이 구조 간선이든 props 흐름이든 같은 색 → 배선과 props 흐름이 한 언어를 쓴다.
- **멀티 흐름은 배선과 커플링**: 여러 흐름을 같은 간선에 또렷이 겹쳐 보이려면 평행 오프셋이 필요하고, 그건 라우팅의 일이다. 그래서 색 스킴을 지금 공유 결정으로 박아두면 배선이 착수될 때 props 흐름이 공짜로 따라온다.
- **점진적**: 멀티 추적 메커니즘(리스트화 + 부모색 + 겹침 타협)은 지금도 독립적으로 유용하고, 완성형만 배선을 기다린다.

## 결과 (Consequences)

- **신규(예상)**: 추적 상태 리스트화(`tracks`), 출발 노드 → 색 함수(배선과 공유), 흐름별 간선/노드 색, 겹침 해소 규칙. 전부 프레젠테이션 — `RenderNode`/스키마 불변([ADR-0032](0032-props-flow-and-change-afterglow.md)와 동일 계층).
- **선행/커플링**: 완성형(평행 색 줄기)은 배선([ADR-0029](0029-orthogonal-edge-routing-deferred.md), 클러터 감쇠 [ADR-0041](0041-edge-clutter-attenuation.md) 이후) 필요. 색 함수의 정확한 정의도 배선과 공동 확정.
- **스코프(지금)**: 방향만 — "간선 색 = 부모" 원칙 + "다중 흐름" 확장 방향. 코드는 아직 안 넣는다(멀티 추적만 원하면 배선 전 버전으로 선구현 가능).
- **되돌리기 쉬움**: 순수 프레젠테이션이라 데이터/레이아웃 불변식과 무관.
