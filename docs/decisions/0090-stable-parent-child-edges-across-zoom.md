# ADR-0090: 확대율과 무관한 실제 부모–자식 간선

- 상태: 채택됨(구현, ADR-0084 대체)
- 날짜: 2026-08-27

## 맥락

ADR-0084는 확대율에 따라 실제 컴포넌트 간선을 파일/그룹 집계선으로 바꿨다. 큰 그래프를
멀리서 요약하기에는 유용했지만, strict waterfall(ADR-0089)에서는 같은 위치의 선이 줌에 따라
다른 관계를 뜻하게 된다. 사용자는 축소·확대 중에 "없어진 선" 또는 "새 관계"로 읽을 수 있고,
회색 집계선도 실제 parent→child 선과 구분하기 어렵다.

## 결정

1. 지도 모드(`<55%`)는 파일 프레임과 라벨만 보이는 개요로 둔다. 관계선을 별도의 집계 표현으로
   바꾸지 않는다.
2. 컴포넌트가 보이는 모든 확대율에서는 동일한 실제 parent→child 간선만 표시한다. 깊이는 색과
   opacity를 조절할 수 있지만 간선의 정체성은 바꾸지 않는다.
3. 파일/그룹 집계선(`edge-group-link`)과 구조 모드(`zoom-mid`)를 제거한다. 중앙 배선 pass도
   실제 cross-group 간선만 입력으로 받는다.
4. 공유 UI는 기존처럼 상시 긴 선 대신 로컬 공유 칩으로 표현하는 예외를 유지한다.

## 결과

- 줌은 관계를 **보이거나 숨기는 것**만 결정하며, 관계의 의미나 출발점은 바꾸지 않는다.
- 회색 반투명 파일 관계선이 사라지고, visible detail에서는 모든 보이는 일반 간선이 실제 Fiber
  부모→자식 관계다. 부모가 뷰포트 컬링되었을 때만 기존의 그룹 프레임 폴백이 유지된다.
- 지도 모드는 연결도 전체가 아니라 공간적 개요로 명확히 역할을 제한한다.
- 다음 밀집 모드는 이 표현 규칙 위의 **별도 레이아웃 정책**이다. 압축하더라도 간선 데이터를
  축약·교체하지 않고, 실제 관계선의 길이·꺾임·가시성만 조절해야 한다.

## 검증

- `SemanticZoomController.test.tsx`: 지도 임계값 이상의 모든 배율이 같은 컴포넌트 관계 모드인지 확인한다.
- `toFlow.test.ts`: 접힌 지도 상태에서 파일 집계 간선을 만들지 않고, 펼쳐진 상태에서 실제
  parent→child 간선과 컬링 프레임 폴백만 만드는지 확인한다.
- `npm run typecheck`, `npm run test`, `npm run verify:edge-clutter`로 화면·배선 회귀를 확인한다.
