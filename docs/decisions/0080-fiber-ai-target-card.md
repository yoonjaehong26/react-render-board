# 0080. 선택 DOM은 Fiber 기반 AI target card로 전달한다

- 상태: 채택됨(구현)
- 날짜: 2026-08-26
- 관련: ADR-0024(보드↔DOM 양방향), ADR-0026(Alt-click/픽 모드), ADR-0038(hover 프리뷰), ADR-0074(코드 맵·불변 규칙)

## 맥락

사용자가 화면의 임의 요소를 코드 에이전트에게 가리키려 할 때 긴 CSS selector는 구조 변경에
약하고, `div:nth-child(3)`는 사람이 무엇을 뜻하는지 설명하지 못한다. 반대로 개발자가 매번
`data-*` 이름표나 접근성 라벨을 소스에 추가하게 하는 방식은 RRB의 즉시 관찰 경험과 맞지
않는다.

RRB는 이미 선택한 host DOM에서 React Fiber를 얻는다. 이 연결을 이용하면, source code를
수정하지 않고도 "어느 이름 있는 React 컴포넌트가 이 요소를 렌더했는가"를 짧게 전달할 수
있다. 다만 `RenderNode`에 이를 넣으면 클릭/hover라는 일시 UI 요구 때문에 커밋 스키마를
확장하게 된다.

## 결정

선택한 DOM을 다음 한 줄 **AI target card**로 만든다.

```
Target: OrderSummary › CheckoutButton › button "결제하기"
```

- `targetContext.ts`가 선택 순간의 host Fiber를 부모 방향으로 걸어, 가까운 이름 있는 composite
  컴포넌트 최대 3개를 root→target 순으로 수집한다.
- 현재 `location.pathname`을 가장 앞에 붙인다(예: `/shop › …`). query/hash는 정렬 상태나
  민감한 값을 길게 복사할 수 있어 기본 전달에서 제외한다. 루트(`/`)는 정보량이 없어 생략한다.
- 마지막 조각은 실제 host의 ARIA/implicit role과 accessible name 후보(`aria-label`,
  `aria-labelledby`, 연결 label, 텍스트)를 쓴다. 이름 없는 요소는 `selected div`처럼 있는
  사실만 말한다.
- 같은 부모 아래 같은 composite Fiber가 반복될 때만 그 인스턴스의 첫 비상호작용 텍스트를
  경로에 붙인다. `heading`·`aria-label`을 첫 DOM 텍스트보다 우선한다. 예:
  `ProductCard ["리넨 셔츠"] › button "담기"`. 대표 텍스트도 겹치거나
  없을 때만 그 반복 범위 안의 `2/9` 순번을 보조로 붙인다. `<ul>`/`<li>` 여부가 아니라 Fiber
  형제 반복을 기준으로 하므로 카드·테이블 행·메뉴·알림에도 같은 규칙이 적용된다.
- 순번·잘린 텍스트처럼 약한 단서가 쓰이면 전광판은 **식별 보조**와 이유를 보인다. role/name이
  없거나 제목 없는 반복 인스턴스처럼 현재 텍스트만으로 충분히 구분할 수 없으면 **식별 불충분**을
  명시한다. 이 상태는 스크린샷·MCP를 자동 실행하지 않는다.
- Alt-hover/픽 모드 hover에는 카드의 **미리보기**만 보인다. Alt-click 또는 픽 성공 시 선택을
  고정하고 `AI용 복사`로 위 문자열을 클립보드에 복사한다. 평소 클릭은 계속 관여하지 않는다.
- 이 상태는 `interactionStore`의 UI side-channel이다. `RenderNode` 스키마, 대상 앱의 DOM/CSS,
  그리고 사용자의 소스 코드를 바꾸지 않는다.
- MCP는 첫 사용 조건이 아니다. 나중에 MCP가 제공되면 같은 카드의 `target_ref`를 도구 입력으로
  확장할 수 있지만, 복사 텍스트만 받은 제3자 에이전트도 현재 형식을 그대로 읽을 수 있어야 한다.

## 기각한 선택지

1. **CSS selector를 기본 전달 형식으로 사용** — 재탐색에는 유용하지만 의미와 React 소유자를
   잃고 sibling 순서 변화에 취약하다. 필요해질 때 디버그용 보조 정보로만 추가한다.
2. **접근성 정보만 사용** — 잘 갖춘 화면에는 좋지만 anonymous `div`와 프로젝트별 접근성 편차를
   해결하지 못한다. Fiber 경로와 결합할 때만 RRB 고유의 식별력이 생긴다.
3. **MCP 연동을 필수화** — 사용자가 별도 연결을 해야 해 첫 경험의 마찰이 커진다. 표준화는
   중요하지만, 먼저 도구 독립적인 복사 형식을 정하고 MCP는 선택적 자동화로 둔다.
4. **컴포넌트 정의 파일 경로를 함께 표시** — 현재 source hint는 정의 위치가 아니라 render/use
   위치라는 불변 의미(ADR-0007)다. 정확한 정의 위치를 약속하지 않는다.

## 결과와 한계

- 개발자가 소스 코드를 손대거나 AI에 MCP를 연결하지 않아도, 선택→복사만으로 의미 있는 지시를
  전달할 수 있다.
- 컴포넌트 이름이 minify/anonymous이거나 선택 요소가 텍스트 없는 `div`이면 정보량은 제한된다.
  이때도 꾸며낸 식별자는 만들지 않는다.
- 화면상 같은 요소를 다시 검증해야 하는 요청, 동일한 빈 div가 많은 화면은 후속으로 **시각 증거
  (선택 영역 캡처)** 와 선택적 selector/DOM 힌트를 붙여 보강한다. 캡처는 무거운 의존성이나
  불안정한 브라우저 API를 기본 경로에 넣지 않기 위해 이번 범위에서 제외했다.
- 구현 중 드러난 기존 FAB 회귀도 함께 고쳤다. 드래그 컨테이너가 `pointerdown`부터 pointer
  capture하면 일반 click의 target이 부모로 바뀌어 내부 "보드 열기" 버튼이 실행되지 않았다.
  이제 6px 드래그 임계값을 넘긴 뒤에만 capture하므로 일반 click과 드래그를 모두 보존한다.
