# ADR-0088: 직접 자식 envelope를 예약하는 읽기 우선 기본 레이아웃

- 상태: 채택됨(구현)
- 날짜: 2026-08-27
- ADR-0087 보완: 압축보다 부모–자식 직선 가독성을 기본 우선순위로 복원

## 맥락

ADR-0087의 밴드별 제약 압축은 빈 공간을 줄였지만, 상위 파일 안의 부모 컴포넌트가 기본
tight-tree 간격으로 다시 붙었다. 실제 React 트리는 다음 커밋에 어떤 자식 파일이 추가될지
예측하기 어렵고, 이 보드에서는 캔버스 폭보다 부모–자식 관계를 즉시 읽는 것이 더 중요하다.

반대로 ADR-0086처럼 모든 후손의 폭을 조상 source까지 재귀적으로 전파하면, 한 깊은 서브트리의
성장만으로 상위 캔버스 전체 폭이 폭발한다.

## 결정

기본 레이아웃을 읽기 우선으로 둔다.

1. 파일 내부에서 cross-group 자식을 직접 렌더하는 **leaf 부모 컴포넌트**에는, 서로 다른 직접
   자식 파일의 기본 frame 폭 합과 파일 간 gap을 가로 슬롯으로 예약한다.
2. 실제 컴포넌트 노드 box 폭은 그대로 유지하고, 예약 슬롯 중앙에 둔다. 추가 폭은 parent→child
   수직 corridor와 같은 parent의 fan-out rail 공간이다.
3. 대상 파일의 폭은 외부 자식 예약을 적용하기 전의 base frame으로 측정한다. 즉 직접 자식의
   손자/후손 폭은 조상 source 슬롯에 포함하지 않는다.
4. 파일 그룹의 x 배치는 ADR-0087의 같은-band 비중첩 제약을 계속 적용한다. source가 이미
   벌어졌으므로, 가능한 관계선은 수직으로 유지되고 충돌하는 그룹만 최소 이동한다.

기본값은 넓고 예측 가능하게 두며, 압축 보기 모드는 실제 사용 중 가로폭이 문제가 된다는 증거가
쌓일 때 별도의 사용자 선택으로 추가한다. 지금은 자동으로 두 정책을 섞어 의미가 바뀌는 것을
피한다.

## 결과

- 자식 파일 수가 많거나 넓은 파일을 직접 렌더하는 부모는 처음부터 이웃 부모와 충분히 떨어진다.
- 새 자식 파일이 생겨도 같은 규칙으로 source 슬롯이 확장되어, 간선이 다시 한 rail로 섞이는
  가능성을 방어한다.
- 깊은 후손 하나 때문에 모든 조상이 폭을 재귀적으로 예약하지 않아 canvas 폭은 직접 관계에
  비례해 증가한다.
- 같은 파일 안에서 자체 자식을 가진 non-leaf source의 전용 슬롯 확장은 후속 과제다. 현재의
  흔한 leaf source(파일 경계를 렌더하는 컴포넌트)부터 보장하며, non-leaf는 기존 tidy-tree
  중심 정렬을 유지한다.

## 검증

- `layout.test.ts`: 넓은 직접 자식 파일에 따라 형제 source 간격이 확장되는지, 넓은 손자 파일이
  조상 source 간격까지 재귀 전파되지 않는지 확인한다.
- `toFlow.test.ts`: 구조 관계선의 실제 source anchor 계약을 유지한다.
- 구조/상세 간선 Playwright 검증으로 프레임 관통·semantic zoom 회귀를 확인한다.
