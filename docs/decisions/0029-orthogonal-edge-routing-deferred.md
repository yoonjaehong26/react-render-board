# ADR-0029: 간선 직교/버스 배선은 보류, 간선 클러터 감쇠를 먼저

- 상태: 채택됨(방향성 — 배선은 보류, 클러터 라운드가 다음 후보)
- 날짜: 2026-07-18

## 맥락 (Context)

현재 보드의 간선은 React Flow 기본 `smoothstep`이다(`src/visualization/lib/toFlow.ts:115-128`) —
두 핸들(source=Bottom / target=Top) 사이를 L/Z자로 그릴 뿐 충돌 회피가 없어 중간에 낀 노드를
관통한다. 사용자가 참고 다이어그램(Excalidraw 수작업, 회로도풍 "버스" 정렬 — 여러 간선이
같은 x/y축 채널로 모였다 갈라짐)을 제시하며 두 가지를 물었다: ① 이런 직교/버스 배선을
도입할 값어치와 난이도, ② 이 다이어그램의 최대 단점이었던 "수백 노드 속 뺴곡한(거의
안 보이는) 간선" 클러터의 최적화 가능성.

제약(뒤집지 않음): 노드 위치는 결정론적 tidy-tree로 고정돼 있고(`layout.ts`), force-directed는
"매 커밋 re-heat"로 이미 기각됨(ADR-0008, [2026-07-17-generic-dataviz-tool-precedents.md]).
동시 배선 간선 수는 이미 화면 한 장 분량으로 제한됨(ADR-0017: 지도 모드는 간선 미생성,
상세 모드는 뷰포트 안 그룹만).

상세 조사·논의는 [`../research/2026-07-18-orthogonal-edge-routing.md`](../research/2026-07-18-orthogonal-edge-routing.md)
(1~7절)에 있다. 이 ADR은 그 결론을 결정으로 박제한다.

## 검토한 대안 (Options)

**배선 엔진 후보** (연구 문서 1절):
- **A. libavoid (Adaptagrams WASM, `libavoid-js` / 드롭인 `avoid-nodes-edge`)** — 커넥터 배선기
  정체성이 정확히 일치(노드 안 옮김), 충돌 회피+버스 nudging+증분을 모두 제공. 단
  WASM ~485KB·LGPL-2.1, 증분 결정론 미검증, 전역 nudging이라 무관한 커밋에 버스가 재배열될
  위험(라이브 안정성 = ADR-0008의 간선 판, 라이브러리가 안 풀어줌).
- **B. 스톡 elkjs ORTHOGONAL** — 막다른 길. Fixed Layout은 배선을 안 하는 pass-through,
  Layered는 노드를 옮김. ELK 자신의 답이 Libavoid라 결국 A로 수렴.
- **C. React Flow smart-edge 플러그인(tisoap/jalez, grid+A*)** — 충돌 회피만, 버스 정렬 없음.
- **D. 자체 grid A*** — 범용 회피 전제로는 큰 작업.
- **E. (후속) 규칙 기반 특화 배선기** — 사용자가 명시한 규칙 4개를 형식화한 결과(연구
  문서 5절), 우리 레이아웃 불변식 위에서는 A~D보다 작고 정확. 그룹 내 버스는 노드 좌표의
  순수 함수라 라이브 안정성이 ADR-0008에서 상속됨(WASM·LGPL·전역 재배열 위험 전부 없음).

**"노드를 간선에 맞춰 움직이면?"** (연구 문서 6절) — 이론상 crossing minimization으로 유효하나,
렌더 트리는 트리라 tidy-tree 그룹 내부 교차가 구조적으로 0. 실익은 그룹 배치 수준에만 있음.

**클러터 처방** (연구 문서 7절, 배선과 별개 축) — a.시각적 감쇠(CSS), b.간선 semantic
zoom/LOD, c.hover 혈통 점등, d.버스 획 병합, e.그룹 내 간선 생략.

## 결정 (Decision)

1. **직교/버스 배선은 지금 MVP에 넣지 않는다** — 막힌 증거가 없다(현행 smoothstep은 동작,
   버스 정렬은 심미 지향이지 결함 리포트 아님. CLAUDE.md "막힌 증거 없이 곁가지 투자 금지").
2. **진행하게 될 경우의 제1후보는 libavoid가 아니라 규칙 기반 특화 배선기(E)** 이며, libavoid는
   스파이크 폴백으로 강등한다.
3. **노드 위치 불가침을 유지**하되, 이를 "영원한 원칙"이 아니라 **"데이터가 트리인 동안의
   원칙"**으로 명문화한다. 데이터 스코프가 many-to-many 간선(store 구독·context 의존 등)으로
   확장되면 제한적 노드 재배열(crossing minimization)을 재검토한다.
4. **간선 클러터 감쇠(7절 a·b)를 배선보다 먼저인 독립 라운드 후보로 둔다** — 이쪽은 "막힌
   증거"(뺴곡함은 실제 관찰된 단점)가 있고 배선기 없이 표현 레이어(스타일/LOD)만으로
   저비용 해소가 가능하다.

## 근거 (Rationale)

- 배선을 보류하는 핵심 이유는 성능이 아니라 **가치·시점**이다. 값어치 있는 버전(버스 정렬)은
  드롭인("작음")이 아니라 라이브 안정성 작업을 동반한 "중간"이고, 남은 UX 백로그(캔버스
  주석/코드 접근/그룹 접기)와 경합한다.
- 규칙 기반 배선기를 제1후보로 올리는 근거는 레이아웃 불변식이다: 트리 + 결정론적 tidy-tree라
  그룹 내 간선은 좌표 산수로 그릴 수 있고 안정성이 공짜(ADR-0008 상속). 이는 4절의 "libavoid가
  유일 현실안" 초기 평가가 **범용** 회피를 전제했기 때문에 나온 것으로, 규칙 형식화 후 뒤집혔다.
- 클러터를 먼저 두는 근거는 잉크-정보 정합성이다: tidy-tree에서 그룹 내 간선은 정보가 이미
  위치에 함축돼 있고(React DevTools는 간선을 안 그림), 그룹 간 간선만 위치로 예측 불가능해
  정보 가치가 높다. 현행은 둘을 같은 무게로 그려 배분이 역전돼 있다.

## 결과 (Consequences)

- **되돌리기 쉬움** — 순수 조사·방향 결정이라 코드 변경 없음. 나중에 배선이 필요해지면 연구
  문서의 후보 비교·규칙 형식화·스파이크 게이트가 그대로 착수 근거가 된다.
- 클러터 감쇠 라운드를 실제 착수하면 별도 ADR로 구현을 기록한다(현행 `flow.css .zoom-far`
  이진 규칙 → 단계형 LOD, `toFlow`의 depth 기반 클래스 분기).
- "노드 위치 불가침 = 트리인 동안만"이라는 단서는 향후 데이터 스코프 확장(ADR-0024 MVP 경계)
  논의와 연결된다 — 그 확장이 배선 전략 전체(트리→일반 그래프)를 다시 열 수 있다.
- 미해소로 남기는 것: 규칙 기반 배선기의 실제 구현 난이도(그룹 간 거터 A*의 세부), libavoid
  증분 결정론, 실측 번들 — 전부 착수 시 스파이크로 확인.
