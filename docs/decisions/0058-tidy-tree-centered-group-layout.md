# ADR-0058: downfall tidy-tree 중앙 정렬 (부모를 자식 스팬 중앙 위에)

- 상태: 채택됨(구현)
- 날짜: 2026-07-18

## 맥락 (Context)

부모 앵커 배치(ADR-0056)는 각 자식 그룹을 부모 중심 x로 당기되 겹치면 오른쪽으로 밀었다. 그 결과 부모가 **자식 무리의 왼쪽 끝** 위에 걸리고, 자식이 많을수록 오른쪽으로 치우쳤다. 사용자 지적: "자식 컴포넌트가 점차 우측으로 치우친다. 이게 직관적인가? 중앙으로 모으는 게(AVL 느낌) 낫지 않나?" — 정확한 관찰이었다. 우측 치우침은 비대칭이라 트리로 읽기 불편하다.

좌→우 순서 기준을 바꾸는 것은 답이 아니었다 — 현재 좌→우는 이미 **렌더 순서**(JSX에 자식을 쓴 순서)라 소스를 읽는 순서와 같아 가장 직관적이다. 문제는 "순서"가 아니라 "부모가 자식 중앙이 아닌 왼쪽 끝에 있는 것"이었다.

## 검토한 대안 (Options)

- **현행 유지(좌측 앵커)** — 단순하지만 우측 치우침 유지.
- **tidy-tree 중앙 정렬** — 채택(사용자 선택). 부모를 자식 스팬 중앙 위에 놓는다(Reingold–Tilford/Walker의 tidy-tree). 대칭적이고 "자식이 많을수록 넓어지고 부모는 그 중앙 유지" — 트리 다이어그램의 정석.
- **개발자 옵션(중앙/좌측 토글)** — 유연하지만 "트리는 중앙 정렬이 거의 정답"이라 실익 대비 UI·복잡도만 늘어 기각(과설계 회피).

## 결정 (Decision)

**평면(폴더 off) 그룹 배치를 tidy-tree 중앙 정렬로 바꾼다.** y는 깊이(밴드) 그대로, x만 tidy-tree로.

- **대표 부모 스패닝 트리.** 그래프는 공유 컴포넌트로 DAG(다중 부모)라 tidy-tree(트리 가정)를 바로 못 쓴다. 각 그룹의 부모 중 **깊이=자기−1**인 것(최장경로라 반드시 존재) 가운데 **groupOrder 최소**를 대표 부모로 골라 스패닝 트리를 만든다. 나머지 부모 연결은 간선으로만 그린다(전부 중앙에 못 놓으므로 — 공유 레인은 후속). 각 대표 부모의 자식 목록은 **렌더 순서(groupOrder)**로 정렬해 좌→우 의미를 유지.
- **tidy-tree x 배정(Walker의 단순형).** post-order로 자식을 먼저 놓고 부모를 **자식 스팬(첫~끝 중심)의 중앙**에 놓는다. 부모가 같은 깊이 왼쪽 형제와 겹치면 오른쪽으로 밀되, 그 **서브트리 전체를 같은 만큼 밀어**(subtree shift) 부모가 자식 위 중앙을 유지하게 한다. `cursor`(깊이별 다음 빈 x)로 겹침 방지. 규모가 작아(그룹 수십~수백) O(n²) shift로 충분.
- **y = 깊이별 최대 높이 누적.** 밴드별로 y를 쌓는다(기존과 동일한 waterfall 세로 흐름).
- **줄바꿈 없음 + x≥0 정규화.** 캔버스 pan/zoom이 넓은 트리를 감당(ADR-0056과 동일 판단). tidy-tree는 x가 음수로 흐를 수 있어 전체를 x≥0로 정규화(노드는 그룹-상대라 영향 없음).
- **PENDING**은 스패닝 트리 밖 — 맨 아래 밴드에 좌→우 순차.
- **안정성**: 깊이·groupOrder·그룹 내부 배치 캐시 불변. 대표 부모/자식 순서/배치 전부 결정적이라 트리가 안 바뀌면 동일(안정). 폴더 중첩(ADR-0053) 경로는 이번 변경 밖(packUnits 유지).

## 근거 (Rationale)

- **우측 치우침의 정확한 해소.** 부모를 자식 중앙에 놓아 대칭 트리가 된다. 실측 — AdvancedPatterns 중심 929 = 자식 4개 스팬 중앙 930(1px 오차). Storefront가 자식 3개 중앙 위, ProductGrid→ProductCard도.
- **렌더 순서 유지.** 좌→우는 그대로 소스 순서라, 중앙 정렬은 순서가 아니라 위치만 바로잡는다.
- **공유 컴포넌트 현실.** 다중 부모는 전부의 중앙에 못 놓으므로 대표 부모 하나 아래로(간선은 남김), 대부분 단일 부모라 중앙 정렬이 깔끔. 나머지는 공유 레인(후속)으로.

## 결과 (Consequences)

- **바뀐 것**: `layout.ts` 평면 배치 블록을 tidy-tree(대표 부모 스패닝 트리 + Walker shift + 밴드 y)로 교체. ADR-0056 부모 앵커 코드는 대체됨. 데이터/노드 내부 좌표 불변.
- **검증**: `tsc` 클린, 유닛 331개 통과(신규/갱신: 부모가 자식 스팬 중앙·치우침 없음, 공유 그룹은 대표(먼저 등장) 부모 아래, 최상위 groupOrder·결정성). Playwright 실측 — AdvancedPatterns가 자식 중앙(오차 1px), 전체가 대칭 트리(스크린샷). 콘솔 에러 0.
- **트레이드오프**: 공유 컴포넌트는 대표 부모 아래만 중앙 정렬(나머지 부모는 긴 간선 — 공유 레인 후속). 넓은 트리는 pan/zoom·지도 모드로. O(n²) shift(규모상 무해).
- **되돌리기**: 배치 블록 한 곳. 데이터/색/컬링/중첩 불변.
- **관련 문서**: 부모 앵커(대체됨) [ADR-0056](0056-downfall-parent-anchored-placement.md), 그룹 waterfall/깊이 [ADR-0034](0034-group-level-waterfall-layout.md), 순서 안정성 [ADR-0008](0008-live-mvp-integration.md), 폴더 중첩 [ADR-0053](0053-folder-nested-grouping.md).

## 다음 (남긴 것)

- **부모 밀림 완화** — subtree shift로 형제 서브트리가 커지면 부모가 밀리는데, 양쪽 균형(Walker의 apportion 완전판)까지는 안 감. 필요 시 후속.
