# ADR-0051: 크로스-그룹 간선 규칙 기반 직교 배선 (ADR-0029 §5)

- 상태: 채택됨(구현, v2 — Hanan-그리드 A*)
- 날짜: 2026-07-18

## 맥락 (Context)

[ADR-0029](0029-orthogonal-edge-routing-deferred.md)가 간선 배선을 보류하며 "진행 시 제1후보는 libavoid가 아니라 **규칙 기반 특화 배선기**(§5)"로 정했다. 이번에 그 배선을 착수하기 전, 두 가지를 실측으로 먼저 확인했다:

1. **그룹 내(부모→자식) 버스는 이미 돼 있다.** React Flow `smoothstep`은 source→중점 채널→target 직교 경로인데, tidy-tree라 형제가 같은 부모(트렁크 x)와 같은 자식 행(채널 y)을 공유해 **자동으로 버스로 정렬**된다(실측: 한 그룹의 fan-out 5간선이 전부 `x=840 트렁크 → y=444 채널 → 자식별 스텁`). 그룹 내 배선은 추가 작업이 필요 없었다.
2. **진짜 문제는 크로스-그룹 간선이다.** 그룹 경계를 넘는 간선은 waterfall 층에 그룹이 빽빽한 실제 앱(excalidraw 80그룹, shadcn-admin 49그룹)에서 중간 그룹 프레임/노드를 직선으로 관통한다. **데모(~15그룹)는 너무 깔끔해 이 문제가 과소평가**됐다(사용자 지적) — 실제 앱 밀도에서 배선이 정당화된다.

## 결정 (Decision)

**크로스-그룹 간선(프레임-폴백 포함)만 커스텀 직교 간선 `ortho`로 배선한다.** 같은-그룹은 smoothstep(이미 버스) 유지, 지도 모드 집계 엣지도 smoothstep 유지.

- **`edgeRouting.ts`(순수 함수)** — `routeOrthogonal(source, target, obstacles)`가 그룹 프레임(장애물)을 피하는 직교 폴리라인을 낸다. 좌표의 순수 함수라 **라이브 안정성이 레이아웃에서 상속**된다(ADR-0008, 새 상태·매 커밋 전역 재배선 없음 — ADR-0029 §5가 규칙 기반을 제1후보로 올린 핵심 근거).
  - 끝점을 담은 프레임(소스/타깃 자기 그룹)은 장애물에서 제외(그 프레임 진입은 정상).
  - **v2 알고리즘 — Hanan-그리드 A***: source·target·장애물 모서리(±margin)의 x·y로 격자(Hanan grid)를 만들고, 격자선(전부 장애물 밖)을 따라 A*로 최소 비용(길이 + 코너당 굽힘 페널티) 직교 경로를 찾는다. 상태에 진입 방향을 넣어 굽힘을 세고, 일직선 점은 병합한다. **우회 경로가 존재하면(항상 존재) 반드시 찾으므로 v1의 "3-세그먼트로 못 풀면 중점 폴백(관통)" 한계가 사라진다** — 벽 사이 좁은 통로도 통과한다(유닛 테스트). A*가 짧고 굽힘 적은 경로를 고르며 공유 격자선을 선호해, 같은 방향 간선이 같은 거터로 모이는 **버스 병합 효과가 부분적으로 딸려온다**.
- **`OrthoEdge.tsx`** — 그 함수를 쓰는 커스텀 React Flow 간선. 장애물(그룹 프레임 rect)은 `EdgeObstaclesContext`로 받는다(Canvas가 flowNodes에서 파생, toFlow data에 안 실어 간선마다 배열 중복을 피함). **A*는 간선당 O(격자²)라 `useMemo`로 끝점 좌표·장애물이 바뀔 때만 재계산**한다(obstacles는 memoize된 안정 참조 → 레이아웃 불변이면 커밋마다 재배선 안 함). className/style은 래퍼에 그대로 실려 색·점선·감쇠 CSS는 smoothstep 때와 동일.
- **라운드 코너** — `pointsToPath`가 코너를 quadratic으로 둥글려(radius 8) 손그림 정체성(ADR-0030)과 어울린다.
- **사용자 피드백 반영(가독성)**: ① **특이점(꺾임·갈라짐)을 그룹 밖 거터에서만** — 처음엔 격자선 배치(`lanePlacement`=30)를 충돌 여백(`collideMargin`=10)과 분리했지만, 자기 소스/타깃 프레임을 "장애물 제외"하면 A*가 **그 프레임 안에서 꺾이는** 문제가 남았다. 그래서 **탈출-후-배선** 구조로 바꿨다: 모든 프레임을 장애물로 두고, 간선은 자기 프레임 밖(거터)으로 곧장 수직 탈출한 뒤(escape) 그 지점부터 A*로 배선한다 — 꺾임·갈라짐이 어떤 프레임 안에서도 안 생긴다(실측: 중간 구간이 프레임을 지나는 간선 0). ② **부모별 레인 분리** — A*가 공유 격자선을 쓰면 다른 부모 경로가 같은 거터에서 겹친다. `laneOffsetForKey(source)`로 소스(부모) id에서 결정론적 레인 오프셋(±6·±12)을 뽑아, **다른 부모는 다른 트랙, 같은 부모는 같은 레인(공유=버스)**. ③ 같은-그룹 간선 depth opacity 바닥을 올려(0.35→0.48 등) "거의 안 보임" 완화. ④ **프레임-폴백 간선(`edge-cross-group-frame`)을 hover 혈통 dim에서 제외** — source가 화면 밖 그룹 프레임이라 혈통 탐색에서 빠져 있어, 예전엔 hover 시 통째로 사라졌다(피드백). 이제 dim 예외라 "저 도메인에서 들어오는 연결"이 hover 중에도 보인다.

## 근거 (Rationale)

- **libavoid(WASM/LGPL)를 안 쓴다.** ADR-0029 §5대로 규칙 기반이 우리 레이아웃 불변식 위에서 더 작고 정확하다: 좌표 순수 함수라 WASM 485KB·전역 nudging 재배열 위험·증분 결정론 미검증이 전부 없다. 안정성은 노드 안정성(ADR-0008)으로 환원된다.
- **크로스-그룹만.** 그룹 내는 smoothstep이 이미 버스라 건드릴 이유가 없다 — 잉크·리스크를 정보 가치 있는 곳(경계 넘는 소수 간선)에만 쓴다.
- **증거 기반.** 데모에서 "관통"이 적어 보였으나(6중 1) 그건 toy 데모 아티팩트였다. 실제 앱(49~80그룹)은 크로스-그룹 밀도가 훨씬 높아 관통이 흔하다 — 배선이 정당화된다.

## 결과 (Consequences)

- **실측**: 데모 상세 줌에서 크로스-그룹 6간선 전부 ortho 경로, **남의 그룹 프레임 관통 0**(거터 배선). `scripts/verify-edge-routing.mjs`(`npm run verify:edge-routing`)로 회귀 가드. 유닛 테스트 8개(`edgeRouting.test.ts` — 장애물 회피, 자기 프레임 제외, 다중 장애물 클리어, **벽 사이 통로 완전 회피(A* 완전성)**, 피드백 폴백, path 생성).
- **v2가 v1을 대체**: v1의 "3-세그먼트+우회, 못 풀면 중점 폴백(관통 가능)"을 Hanan-그리드 A*로 교체해 **완전 회피**를 보장한다(우회로가 있으면 반드시 찾음).
- **남은 것(v3)**: ① **간선 간 교차 최소화 + 명시적 버스 획 병합(7절 d, 규칙 8)** — 현재는 간선별 독립 A*라 서로 다른 부모의 경로가 채널에서 **교차**할 수 있고(피드백), 한 부모의 여러 간선을 트렁크+바로 "명시적으로" 합치는 회로도풍 정렬도 없다. 둘 다 채널 안에서 간선 순서를 배정하는 **coordination pass**(간선 간 좌표 공유, metro-line crossing minimization)가 필요하다 — v2의 간선별 순수 함수 구조를 넘어서는 부분이라 별도 라운드. ② 실제 앱(excalidraw/shadcn) 대규모 실측 — 9000노드 렌더가 자동화 도구를 막아 미완(데모+유닛으로 검증). ③ 초대형에서 A* 격자 비용 프로파일링(현재는 bbox 제한 + memoize로 충분).
- **성능**: 크로스-그룹 간선은 소수(수십)라 간선당 O(장애물 수) 경로 계산이 가볍다. 장애물은 그룹 프레임(수십)뿐이고 `EdgeObstaclesContext`로 공유해 간선마다 재계산 안 함.
- **되돌리기 쉬움**: `type:'ortho'`를 `'smoothstep'`으로 되돌리면 끝(edgeTypes/함수는 남아도 무해). 데이터·레이아웃 불변.
