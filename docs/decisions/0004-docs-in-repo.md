# ADR-0004: 문서를 GitHub 레포의 `.md`로 관리

- 상태: 채택됨
- 날짜: 2026-07-17

## 맥락

대규모 프로젝트라 문서화가 중요하다. Notion MCP / Obsidian / GitHub `.md` 중 무엇으로 할까?

## 검토한 대안

- **Notion MCP** — 최근 토큰 효율 개선(마크다운 API 등)됐지만, ① API 왕복 오버헤드가 로컬 파일보다 큼 ② 코드는 Git, 문서는 Notion으로 분리돼 PR 하나로 함께 리뷰 불가 → 오픈소스 흐름과 안 맞음.
- **Obsidian** — 개인 사고 정리(백링크/그래프뷰)엔 강점. 단 "공식 프로젝트 문서"로는 vault를 열어야 접근 가능한 진입장벽.
- **GitHub 레포 `.md`** — 로컬 파일이라 AI 에이전트가 오버헤드 없이 읽음. 코드+문서를 같은 PR로 버전 관리·리뷰 가능.

## 결정

**GitHub 레포의 `.md`로 관리한다.**

## 근거

- 오픈소스 기여자의 기대 흐름(클론 → docs 읽기 → 코드 수정 → PR)과 일치.
- AI 코딩 에이전트가 로컬에서 바로 참조 가능.

## 결과

- **절충안:** Obsidian vault를 레포 `docs/` 폴더로 지정하면, 같은 파일을 Obsidian에선 그래프뷰로(사고 정리), GitHub에선 마크다운으로(공식 문서) 겸용 가능. 둘 중 택일이 아니라 겹쳐 쓴다.
- 결정 로그는 `docs/decisions/`에 ADR 형식으로 축적.
