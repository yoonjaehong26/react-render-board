# ADR-0086: 서브트리 폭 예약과 실제 부모 출발점의 waterfall 관계선

- 상태: 부분 대체됨 — 실제 source 관계선/버스 분리는 유지, 상위 폭 전파는 ADR-0087로 대체
- 날짜: 2026-08-26

## 맥락

ADR-0085는 부모 파일 안의 실제 렌더 앵커 순서로 자식 파일을 정렬해, 반대 순서에서 생기는
명백한 교차를 줄였다. 그러나 밴드별로 그 시점의 파일 프레임만 충돌하지 않게 패킹하면, 폭이 큰
자식 파일 또는 그 후손이 다음 부모 가지의 수평 영역으로 들어갈 수 있다. 또한 구조 줌의 집계선이
`파일 프레임 중심 → 파일 프레임 중심` 하나로 축약되어, 같은 파일 안의 서로 다른 부모 컴포넌트가
각각 무엇을 렌더했는지 다시 잃었다.

"모든 선을 수직선으로"은 한 컴포넌트가 여러 파일을 렌더하는 fan-out과 DAG 공유 관계 때문에
일반적으로 불가능하다. 대신 서로 다른 부모 가지가 같은 수평 corridor를 공유하지 않게 만들면,
각 가지 안의 필요한 분기만 남고 교차의 원인을 제거할 수 있다.

## 결정

평면 파일 waterfall에 두 규칙을 적용한다.

1. 공유 레인을 제외한 각 파일 그룹에 보이지 않는 서브트리 envelope를 계산한다.

   ```text
   envelope(parent) = max(frameWidth(parent), Σ envelope(child) + siblingGap)
   ```

   루트와 형제는 frame 폭이 아니라 envelope 폭으로 배치한다. 부모 프레임은 envelope 중앙에 두고,
   자식 envelope는 그 아래에서 좌→우로 나눈다. 자식 순서는 ADR-0085의 실제 JSX 렌더 앵커 순서를
   유지한다.

   이 규칙은 파일 프레임 사이에만 적용하지 않는다. 같은 파일 안에서 외부 파일을 렌더하는 **leaf
   부모 컴포넌트**도, 자신이 렌더하는 서로 다른 자식 파일 frame 폭의 합을 가로 슬롯으로 예약한다.
   실제 노드 박스의 폭은 고정하고 슬롯 안에 중앙 배치한다. 따라서 `DemoApp`처럼 한 파일 안에
   부모 컴포넌트가 많이 있어도, 넓은 자식 트리를 가진 source부터 서로 떨어져 전용 수직 corridor를
   확보한다. 직접 자식 폭이 다시 넓어진 경우까지 반영하도록 내부 배치를 두 번 수렴시킨다.

2. 지도/구조 줌의 파일 관계선을 `(부모 파일, 자식 파일)` 하나가 아니라
   `(실제 부모 컴포넌트, 자식 파일)` 하나로 집계한다. 같은 부모 컴포넌트가 같은 파일의 여러
   인스턴스를 렌더할 때만 하나로 합친다. 구조 줌에서는 선의 시작점을 부모 컴포넌트 하단으로
   잡고, 지도 줌에서는 세부 노드가 보이지 않으므로 기존 파일 프레임 중심으로 단순화한다.

중앙 버스 배선기는 이 실제 부모 컴포넌트 anchor key를 source로 사용한다. 따라서 다른 컴포넌트에서
출발한 관계선은 같은 파일 프레임 안에 있더라도 서로 다른 버스·트랙·예약 corridor를 갖는다.
다중 부모 공유 그룹은 계속 ADR-0061의 공유 레인/로컬 사용처 칩으로 표현하며, 이를 일반 트리에
억지로 넣지 않는다.

## 결과

- 부모 파일은 시각적으로 넓어지지 않지만, 자손이 넓은 부모 가지는 필요한 만큼 가로 공간을 먼저
  확보한다. 한 가지의 후손이 이웃 부모 가지 아래로 침범하지 않아 부모 간 간선 교차가 구조적으로
  사라진다. 그 파일 안의 source 컴포넌트도 같은 폭을 예약해, 바깥만 넓고 부모 노드가 밀집하는
  불일치를 없앤다.
- 구조 줌에서 관계선의 출발 위치가 실제 부모 컴포넌트와 일치해, “어느 파일”뿐 아니라 “파일 안의
  어느 부모가 렌더했는가”까지 읽을 수 있다.
- 같은 부모의 fan-out은 의도된 하나의 trunk/rail을 공유한다. 서로 다른 부모 간에는 공통 선분을
  만들지 않는다.
- 다중 부모 DAG, 화면 폭, 긴 파일명 때문에 모든 꺾임을 0으로 보장하지는 않는다. 보장 범위는
  **서로 다른 primary 부모 서브트리의 수평 영역 비중첩**과 **서로 다른 실제 부모 source의 버스
  분리**다. 필요한 꺾임은 부모 전용 rail 안에서만 발생한다.

## 검증

- `layout.test.ts`: 넓은 자식 서브트리 뒤에 다음 루트 가지가 놓이는지, 같은 파일의 형제 source가
  자신이 렌더하는 파일 폭만큼 벌어지는지 확인한다.
- `toFlow.test.ts`: 다른 부모 컴포넌트에서 같은 파일로 가는 구조 관계선이 별도 source anchor를
  갖는지 확인한다.
- `verify:edge-clutter`, `verify:edge-routing`: 구조/상세 줌의 회귀를 브라우저에서 확인한다.
