# ADR-0084: 파일/그룹 관계를 기본 간선 표현으로 하는 semantic zoom

- 상태: 대체됨(ADR-0090)
- 날짜: 2026-08-26

## 맥락

상세 보드에서 한 파일 그룹이 여러 컴포넌트를 렌더하면, 동일한 `부모 파일 → 자식 파일` 관계가 컴포넌트 간선 수만큼 반복됐다. 직교 배선·트랙 분리·예약 corridor(ADR-0054, ADR-0082, ADR-0083)는 서로 다른 부모가 같은 선로를 쓰는 문제를 줄였지만, 넓은 화면에서 수십 개의 세부 선을 동시에 읽어야 하는 문제 자체는 남았다.

기존에도 지도 모드에는 그룹쌍당 하나의 `edge-group-link`가 있었지만, `zoom < 0.55`에서만 표시됐다. 컴포넌트가 보이기 시작하는 55% 이상에서는 집계선을 숨기고 모든 개별 cross-group 간선을 즉시 되살려, 가장 자주 쓰는 중간 줌에서 다시 선이 난잡해졌다.

## 결정

간선 semantic zoom을 다음 세 표현 레벨로 고정한다.

| 줌 | 주된 관계선 | 컴포넌트 |
| --- | --- | --- |
| `< 0.55` 지도 모드 | 파일/그룹 집계 버스 | 숨김 |
| `0.55 ≤ zoom < 0.9` 구조 모드 | 파일/그룹 집계 버스 | 표시 |
| `≥ 0.9` 상세 모드 | 컴포넌트↔컴포넌트 간선 | 표시 |

- 집계선은 `(부모 그룹, 자식 그룹)` 쌍당 하나다. 같은 파일쌍을 넘는 여러 컴포넌트 연결은 이 하나로 축약한다.
- 집계선도 `ortho`로 렌더하고 중앙 버스 배선 pass에 넣는다. 같은 부모 파일의 여러 자식 파일은 트렁크 하나에서 분기하고, 다른 부모 파일의 경로는 기존 span 트랙·예약 corridor 규칙을 쓴다.
- 중앙 배선 pass는 현재 표현 레벨의 간선만 입력으로 받는다. 보이지 않는 상세선이 구조 버스의 레인을 예약하거나, 보이지 않는 그룹선이 상세 배선을 바꾸지 않는다.
- prop 추적, hover 혈통, afterglow처럼 사용자가 명시적으로 관심을 준 개별 간선은 구조 모드에서도 예외로 남긴다. `지도에서도 상세` 토글도 기존처럼 유지한다.
- JSX/그룹의 배치 순서는 바꾸지 않는다. 이 ADR은 레이아웃 재정렬이 아니라 **표현의 추상화**다.

## 결과

- 기본 탐색 줌에서 상단의 긴 수평선과 수직선 다발이 그룹 관계 버스로 축약된다.
- `SemanticZoomController`는 구조 구간을 `구조 모드 (파일 관계)`로 명시한다.
- `verify:edge-clutter`는 구조 줌에서 개별 cross-group 간선 opacity=0 및 집계 버스 표시를 검증한다. `verify:edge-routing`은 실제로 구조 줌을 벗어날 때까지 확대해 상세 배선만 검사한다.
- 데이터 스키마·그룹/컴포넌트 배치·수동 접기·상세 추적 API는 변하지 않는다.
