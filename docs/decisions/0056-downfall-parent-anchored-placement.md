# ADR-0056: downfall 부모 앵커 그룹 배치 (자식을 부모 아래로)

- 상태: 채택됨(구현)
- 날짜: 2026-07-18

## 맥락 (Context)

그룹 간 배치(ADR-0034)는 그룹을 깊이(층)별로 나눠 각 층을 **왼→오로 등장 순서대로 채우고**, 층이 너무 넓으면 줄바꿈했다. 사용자가 "이 그룹 배치가 누구나 납득 가능한 구조냐"고 물어 실측해보니 두 문제가 드러났다:

1. **같은 깊이가 두 줄로 갈라져 보임.** DemoApp의 자식 그룹 10개는 전부 깊이 1인데 한 줄에 안 들어가 줄바꿈돼, 계층이 다른 것처럼 오해됐다.
2. **자식이 부모 아래에 없음.** 각 층을 등장 순서로 채우다 보니, 예컨대 `AdvancedPatterns`의 자식(ClassCounter 등)이 맨 왼쪽에 배치되고 부모는 오른쪽에 있어, 둘이 멀고 긴 선이 가로질렀다.

앞서 "밴드 안 좌우 순서를 barycenter로"(ADR-0034 후속 시도)를 넣었으나 실측상 **no-op**이었다 — 깊이 1 그룹 10개가 전부 부모가 DemoApp 하나라 재정렬할 기준이 없었다. 즉 문제는 "밴드 안 순서"가 아니라 **"자식을 부모 x 아래로 모으지 않는 것"**이었다.

## 검토한 대안 (Options)

- **밴드 안 barycenter 재정렬(부모 순위 평균으로 좌우 순서만)** — 시도했으나 단일 부모가 지배적인 실제 트리에선 no-op. 순서만 바꿀 뿐 자식을 부모 x로 끌어오지 못한다.
- **부모 앵커 배치(자식 무리를 부모 중심 x 아래로)** — 채택. 밴드를 위→아래로 처리하며 각 그룹의 중심 x를 기록하고, 다음 밴드는 "부모 중심들의 평균 x"를 목표로 그 순서대로 겹치지 않게 배치한다. 부모→자식 선이 짧아지고 "누가 누구를 렌더하는지"가 트리 다이어그램처럼 바로 읽힌다.
- **Reingold–Tilford(부모를 자식 스팬 중앙 위에)** — 더 정갈하지만 서브트리 폭 계산 등 2패스가 필요하고, 우리 그래프는 트리가 아니라 공유 컴포넌트로 DAG라 그대로 적용이 어렵다. 후속 여지로 남긴다.

## 결정 (Decision)

**평면(폴더 off) 배치를 부모 앵커 방식으로 바꾼다.**

- **목표 x = 이미 배치된 부모 그룹들의 중심 평균.** 부모가 여럿(공유 컴포넌트)이면 평균이라 부모들 사이에 놓인다. 부모가 없으면(루트/PENDING) 순차 패킹.
- **배치**: 각 밴드에서 목표 x 오름차순(같으면 groupOrder tiebreak)으로 왼→오 진행하며, `max(직전 오른끝, 목표 왼쪽 모서리)`에 놓아 **겹치지 않으면서 부모 아래에 최대한 붙인다**(우선순위법의 단순형).
- **줄바꿈 폐지.** 캔버스는 pan/zoom이라 폭 제한을 두지 않는다 — 줄바꿈이 오히려 부모-자식 정렬을 깨서다. 대신 배치 후 x가 음수로 흐를 수 있어 전체를 x≥0로 **정규화**(노드는 그룹-상대라 영향 없음, 프레임 x만 이동).
- **안정성**: 깊이 banding·groupOrder·그룹 내부 배치 캐시는 그대로. 부모 위치에서 파생하므로 트리가 안 바뀌면 결정적(안정). 폴더 중첩(ADR-0053) 경로는 이번 변경 밖(packUnits 유지).

## 근거 (Rationale)

- **문제의 정확한 해소.** "자식이 부모 아래 없음"이 원인이라, 밴드 안 순서(no-op)가 아니라 부모 x 앵커가 맞다. 실측 — AdvancedPatterns 중심 978에 첫 자식 ClassCounter 중심 978로 정렬(이전엔 맨 왼쪽), Storefront 자식/ProductGrid→ProductCard도 부모 아래로.
- **실제 프론트 개발 고려.** 공유 컴포넌트=다중 부모는 부모 중심 평균으로 부모들 사이에 놓고(유닛), 넓은 fan-out은 줄바꿈 대신 pan/zoom으로 감당(트리는 원래 넓고 사람은 팬한다 — DevTools 트리 모델). 마운트/언마운트는 실제 구조 변화라 재배치가 옳다.
- **저위험.** 그룹 내부 배치/캐시/깊이/순서 상태 불변, x 좌표 배치 로직만 교체. `folders`·중첩 경로 무관.

## 결과 (Consequences)

- **바뀐 것**: `layout.ts` 평면 배치 블록(부모 앵커 + 정규화), `computeGroupDepths`가 `parents` 그래프도 반환. no-op이던 `orderBandsByBarycenter`는 제거. 데이터/노드 내부 좌표 불변.
- **검증**: `tsc` 클린, 유닛 329개 통과(신규: 부모 아래 배치, 최상위 밴드 groupOrder 유지·결정성, 공유 그룹은 부모들 사이 중앙). Playwright 실측 — AdvancedPatterns 자식이 부모 x(978)에 정렬, 전체가 트리 형태(스크린샷). 콘솔 에러 0.
- **트레이드오프**: 줄바꿈을 없애 한 밴드가 넓어질 수 있다(pan/zoom·지도 모드로 감당). 자식 무리는 부모 x에서 오른쪽으로 퍼져 완전 중앙 정렬은 아니다(Reingold–Tilford는 후속).
- **되돌리기**: 배치 블록 한 곳. 데이터/색/컬링/중첩 로직 불변.
- **관련 문서**: 그룹 waterfall [ADR-0034](0034-group-level-waterfall-layout.md), 순서 안정성 [ADR-0008](0008-live-mvp-integration.md)·[ADR-0018](0018-map-mode-lod-and-camera-refit.md), 리스트 접기(폭 감소) [ADR-0046](0046-list-coalescing.md), 폴더 중첩 [ADR-0053](0053-folder-nested-grouping.md).
