# ADR-0085: 실제 렌더 앵커를 따르는 edge-aware waterfall 배치

- 상태: 채택됨(구현)
- 날짜: 2026-08-26

## 맥락

파일/그룹 집계 버스(ADR-0084)로 세부 간선 수를 줄여도, 자식 파일 그룹의 x 위치가 단순 최초 등장
순서에 가까우면 부모 파일 내부의 실제 렌더 컴포넌트와 어긋난다. 그 결과 선은 요약됐지만 긴 수평
이동과 교차 가능성이 남아 waterfall으로 읽히지 않았다.

React 렌더 트리의 형제 순서는 대체로 JSX 렌더 순서와 같고, 이 보드의 그룹 내부 tidy-tree도 그 순서를
보존한다. 따라서 그룹 간 배치도 “부모 파일의 중심”이 아니라 **부모 파일 안에서 자식 파일을 실제로
렌더한 컴포넌트의 x 위치**를 사용하면, 소스 순서와 간선 최적화를 동시에 만족시킬 수 있다.

## 결정

평면 파일 그룹 배치를 render-anchor waterfall으로 바꾼다.

1. 각 cross-group 관계에서 부모 컴포넌트의 그룹-상대 중심 x를 수집한다.
2. 동일 `(부모 파일, 자식 파일)` 관계가 여러 인스턴스를 가지면 중심값의 중앙값을 앵커로 쓴다.
3. 깊이 밴드를 위에서 아래로 배치한다. 자식 파일의 목표 중심은 `부모 frame.x + render anchor`다.
4. 같은/인접한 앵커 때문에 프레임이 겹치는 자식은 compact block으로 묶어 앵커 평균 아래 중앙에 둔다.
   즉, 한 컴포넌트의 fan-out은 하나의 수직 트렁크 아래에서만 분기한다.
5. 충분히 떨어진 앵커의 자식은 각각의 출발점 아래에 둔다. 밴드 안의 frame 충돌은 최소 간격으로만
   해소한다.
6. 다중 부모 그룹은 기존 공유 UI 레인(ADR-0061) 규칙을 그대로 따른다.

최초 등장 순서는 앵커가 없거나 완전히 동률일 때의 안정적 tie-breaker로만 남긴다. 따라서 JSX 순서와
live commit 안정성은 지키되, 간선의 길이·교차 감소가 그룹 x 배치의 주된 목표가 된다.

## 결과

- 서로 다른 부모 컴포넌트에서 나온 자식 파일은 각 출발점의 좌→우 순서를 따라 배치돼 교차가
  배치 단계에서 줄어든다.
- 같은 출발 컴포넌트의 여러 자식은 그 출발점 아래 중앙에 배치돼 parent-over-children 대칭성과
  버스 트렁크가 유지된다.
- x가 음수가 되는 첫 fan-out도 최종 정규화 전에는 허용한다. 처음부터 0으로 clamp하면 묶음이
  오른쪽으로 밀려 부모가 첫 자식 위에 서는 기존 치우침이 재발한다.
- `layout.test.ts`는 역순으로 발견된 두 자식 파일도 실제 부모 컴포넌트 앵커 순서대로 놓이는지
  검증한다. 데이터 스키마·그룹 내부 배치·폴더 중첩 경로는 바꾸지 않는다.
