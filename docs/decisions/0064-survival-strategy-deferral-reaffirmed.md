# ADR-0064: 생존 전략 논의 — MVP 배포(트리거 도달) 후에도 보류 재확인

- 상태: 채택됨
- 날짜: 2026-07-18

## 맥락 (Context)

[ADR 없이 vision.md 7-2](../vision.md)가 "프로젝트를 완성한 뒤 생존 전략(오픈소스화·도그푸딩·포트폴리오 중 무엇에 힘을 쏟을지)을 결정한다"고 명시적으로 보류해 뒀다. 그 보류에는 조건이 붙어 있었다 — **"기능을 전부 완성한 뒤"가 재개 트리거**다.

문서-현실 정합성 검토(5축 리뷰)에서 이 트리거가 사실상 도달했음을 확인했다:

- npm `0.2.0`이 MIT로 **실제 배포**됨(ADR-0062).
- 엔진(훅킹→데이터→시각화) 완성, 3개 번들러 `install`→캔버스 실측(ADR-0036/0042/0062).
- 확인된 결함 5건(P0~P4) 해소, UX 후보 표 소진, 배선/시각 언어 다수 라운드 완료.
- 남은 백로그는 재분류 결과 **전부 optional polish**(배선 v3 Phase 4, 라벨 declutter, 코드 점프 등) — ship-blocker 0건.

즉 "완성 후 재개"의 "완성"에 도달했으므로, 이 시점에서 생존 전략을 **지금 열 것인가**를 의식적으로 판단해야 했다.

## 검토한 대안 (Options)

- **A. 도그푸딩 먼저** — 실제 프로젝트에 붙여 첫 실사용 마찰을 측정(3축 갭 "사용됨의 증거 없음" 해소). 홍보 전에 도구가 스스로에게 유용함을 증명.
- **B. 공개/홍보 착수** — 이미 npm·MIT로 나갔으니 GitHub 다듬기(스크린샷·데모 GIF) + 커뮤니티 노출. 사용자 유입이 동기의 원천이라는 베팅.
- **C. 메모리 누수부터 확정** — 2축의 유일한 실질 리스크(장시간 세션 누수)를 격리 재실행으로 먼저 제거.
- **D. 전략 논의 계속 보류** — 지금 결정하지 않고 "완성 우선" 기조로 남은 optional polish를 계속 다듬는다.

## 결정 (Decision)

**대안 D — 전략 논의를 계속 보류한다.** MVP 배포로 트리거가 도달했음을 기록하되, 오픈소스 확산/도그푸딩/포트폴리오 중 어디에 힘을 쏟을지는 **여전히 확정하지 않는다.** 남은 시각/배선 polish를 "완성 우선" 기조로 이어간다.

## 근거 (Rationale)

vision.md 7-2의 원 논리 — **"완성 전에 이 질문을 붙들면 오히려 병목이 된다"** — 를 트리거 도달 후에도 유지하기로 한 소유자 판단이다. 트리거가 "반드시 지금 결정하라"는 강제가 아니라 "결정해도 되는 시점"일 뿐이라는 해석.

부수적으로, **MIT로 npm에 올린 행위 자체가 이미 오픈소스 경로로 반쯤 발을 디딘 것**이라, 명시적 전략 확정 없이도 방향은 잠정적으로 그쪽에 기운 상태가 유지된다. 능동적 확산 노력(홍보·커뮤니티)만 계속 미루는 것이므로 되돌릴 것이 없다.

## 결과 (Consequences)

- 재구현/기능 스코프는 **여전히 축소하지 않는다**(ADR와 vision.md 7-2의 기존 함의 유지).
- 커뮤니티 확산·홍보 같은 "전략 종속" 작업은 백로그에 넣지 않는다 — 다음 재개 트리거는 "남은 optional polish도 소진됐을 때" 또는 소유자가 임의로 여는 시점.
- **주의로 남기는 엔진 항목 하나**: 2축 검토에서 "메모리 누수 미확정"(60Hz 200초 +10MB, ADR-0013)이 배포·장시간 실사용 관점에서 유일하게 우선순위가 오르는 미해결 질문으로 확인됐다. 전략과 무관한 기술 항목이므로, 보류와 별개로 "완성" 작업 중 격리 재실행으로 확정할 후보다. (나머지 2건 — groupHint 급락·배율 공식 — 은 나중/불필요로 강등.)
- 이 결정은 언제든 재개 가능(보류의 재확인일 뿐, 문을 닫은 게 아니다).
